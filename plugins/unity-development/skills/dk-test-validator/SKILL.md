# DK-Test-Validator

테스트 코드가 올바른 이름과 내용을 갖추고 있는지, 실제로 필요한 테스트인지 검토하고 개선을 권장하는 스킬.

## 전제 조건

- **인풋**: 아래 중 하나
  - 검토할 테스트 파일 또는 디렉터리 경로 (생략 시 전체 테스트 대상)
  - 검토할 테스트 클래스명 또는 메서드명
- **아웃풋**:
  - 검토 결과 보고 (항상)
  - 수정이 필요한 항목에 대한 개선 권장 사항

---

## 워크플로우

### Step 0: 인자 확인

`$ARGUMENTS`를 확인한다.

- **인자 없음**: 프로젝트 전체 테스트를 대상으로 Step 1을 진행한다.
- **인자 있음**: 지정된 파일, 디렉터리, 클래스명 또는 메서드명을 대상 범위로 한정하여 Step 1을 진행한다.

---

### Step 1: 테스트 파일 수집

대상 범위의 테스트 파일 전체를 수집한다.

```bash
# 전체 테스트 파일 탐색 (인자 없는 경우)
find Assets/Tests -name "*Tests.cs" -o -name "*Test.cs" 2>/dev/null

# 특정 경로 지정 시
find {지정 경로} -name "*.cs" 2>/dev/null
```

수집된 파일 목록과 총 테스트 수를 사용자에게 알린다.

```
🔍 검토 대상: {N}개 파일 / {M}개 테스트
```

---

### Step 2: 테스트명 적합성 검토

각 테스트 클래스명과 메서드명이 테스트 내용을 사용자의 언어로 쉽게 이해할 수 있도록 작성되었는지 검토한다.

**테스트명 기준**:

- 클래스명: 검증 대상 클래스 또는 시스템을 명확히 나타내는가
- 클래스명: 클래스 내 테스트 메서드들의 내용을 포괄하는 적절한 이름인가
- 클래스명·메서드명: 예약어가 아닌 이상 "테스트", "Test" 등의 문구를 이름에 포함하지 않는가 (클래스·메서드의 이름 자체가 무엇을 검증하는지 이미 나타내므로 불필요)
- 메서드명: 아래 세 가지 요소를 포함하는가
  - **어떤 상황에서** (조건)
  - **어떤 동작을 했을 때** (행위)
  - **어떤 결과를 기대하는가** (기대값)
- 해당 프로그래밍 언어에서 허용된다면 사용자의 언어(한국어 등)로 작성되었는가

**개선 권장 예시**:

| 기존 | 개선 |
|------|------|
| `Test1()` | `최대치_초과_입력시_예외를_던진다()` |
| `TestHeart()` | `하트가_0개일때_회복_요청하면_변화없음()` |
| `CheckValid()` | `유효하지_않은_ID로_조회하면_null을_반환한다()` |

---

### Step 3: 불필요한 테스트 검토

각 테스트를 아래 5가지 기준으로 검토하여 제거 또는 수정이 필요한 테스트를 식별한다.

| 기준 | 설명 | 권장 처리 |
|------|------|-----------|
| **로직 없는 코드 테스트** | 생성자, 단순 getter/setter, 상수 반환 등 로직이 없는 코드를 테스트함 | 제거 권장 |
| **테스트 보장 범위 초과** | 외부 라이브러리·패키지·프레임워크의 동작을 검증함 | 제거 권장 |
| **UI 표시 여부만 확인** | 특정 UI 요소가 활성화/비활성화되었는지만 확인하고 동작은 검증하지 않음 | 제거 또는 동작 검증으로 수정 권장 |
| **구현 내용을 그대로 사용** | 테스트가 구현 코드의 내부 로직을 그대로 복제하여 항상 통과함 | 수정 권장 (독립적인 기대값으로 재작성) |
| **내부 구현 변경에 취약** | private 메서드 직접 호출, 내부 상태 직접 접근 등으로 구현 변경 시 쉽게 깨짐 | 수정 권장 (공개 인터페이스 기반으로 재작성) |

---

### Step 4: 결과 보고

검토가 완료되면 아래 형식으로 결과를 보고한다.

```
📋 테스트 검토 결과

─────────────────────────────
✅ 적합한 테스트: {N}개
⚠️  개선 권장:   {M}개
🗑️  제거 권장:   {K}개
─────────────────────────────

## 테스트명 개선 권장

{파일경로}
  [{메서드명}]
  → 개선안: {개선된 테스트명}
  → 이유: {이유}

...

## 불필요한 테스트 제거 권장

{파일경로}
  [{메서드명}]
  → 이유: {해당 기준 설명}

...

## 수정 권장

{파일경로}
  [{메서드명}]
  → 문제: {문제 설명}
  → 개선 방향: {개선 방향}

...
```

적합한 테스트만 있는 경우:

```
✅ 모든 테스트가 적합합니다.
```

---

### Step 5: 수정 범위 선택

보고 후 사용자에게 수정 범위를 선택하게 한다.

```
위 항목을 수정할까요?
1) 전체 수정 (모든 개선·제거 항목 대상)
2) 선택 수정 (수정할 항목 번호를 알려주세요)
3) 취소 (보고만 확인)
```

- **1) 전체 수정**: 보고된 모든 항목을 대상으로 Step 6을 진행한다.
- **2) 선택 수정**: 사용자가 지정한 항목만 대상으로 Step 6을 진행한다.
- **3) 취소**: 수정 없이 스킬을 종료한다.

---

### Step 6: 항목별 변경 내용 확인 및 적용

Step 5에서 선택된 항목을 적용하기 전에 진행 방식을 먼저 확인한다.

```
진행 방식을 선택해 주세요.
1) 일괄 적용 (모든 항목을 확인 없이 한번에 적용)
2) 개별 확인 (항목마다 Before/After를 보여주고 하나씩 확인)
```

- **1) 일괄 적용**: 선택된 항목 전체를 즉시 적용하고 Step 7로 이동한다.
- **2) 개별 확인**: 아래 절차에 따라 항목을 하나씩 보여주고 확인 후 적용한다.

각 항목마다 아래 형식으로 변경 내용을 보여준다.

**테스트명 변경 (클래스명 또는 메서드명)**:
```
[{순번}/{전체}] 테스트명 변경
파일: {파일경로}

  Before: {기존 이름}
  After:  {변경될 이름}

적용할까요? (예 / 아니요 / 전체 적용 / 중단)
```

**테스트 내용 수정**:
```
[{순번}/{전체}] 테스트 내용 수정
파일: {파일경로}
대상: {클래스명}.{메서드명}
이유: {수정 이유}

  Before:
  {기존 테스트 코드}

  After:
  {수정될 테스트 코드}

적용할까요? (예 / 아니요 / 전체 적용 / 중단)
```

**테스트 삭제**:
```
[{순번}/{전체}] 테스트 삭제
파일: {파일경로}
대상: {클래스명}.{메서드명}
이유: {삭제 이유}

  삭제될 코드:
  {삭제될 테스트 코드}

적용할까요? (예 / 아니요 / 전체 적용 / 중단)
```

**응답 처리**:
- **예**: 해당 항목을 적용하고 다음 항목으로 진행한다.
- **아니요**: 해당 항목을 건너뛰고 다음 항목으로 진행한다.
- **전체 적용**: 남은 항목을 확인 없이 모두 적용한다.
- **중단**: 남은 항목을 모두 건너뛰고 Step 7로 이동한다.

---

### Step 7: 적용 결과 보고

모든 항목 처리가 완료되면 결과를 보고한다.

```
✅ 적용 완료

─────────────────────────────
✔ 적용됨:    {N}개
✖ 건너뜀:    {M}개
─────────────────────────────

적용된 항목:
  - {파일경로}: {변경 내용 한 줄 요약}
  ...

건너뛴 항목:
  - {파일경로}: {변경 내용 한 줄 요약}
  ...
```

적용된 항목이 없는 경우:

```
변경된 내용이 없습니다.
```

---

### Step 8: 테스트 전체 실행 확인

Step 7에서 적용된 항목이 하나 이상 있는 경우 전체 테스트를 실행하여 통과 여부를 확인한다.

- **EditMode 테스트** 먼저 실행
- 테스트 실패 시: 실패 원인을 분석하고 사용자에게 보고한 뒤 대기한다. 자동으로 되돌리지 않는다.

```
🧪 전체 테스트 실행 중...

✅ 모든 테스트 통과 ({N}개)
```

실패가 있는 경우:

```
❌ 테스트 실패

  - {실패한 테스트명}: {실패 원인 요약}
  ...

수정된 내용으로 인해 발생한 실패인지 확인해 주세요.
```

적용된 항목이 없는 경우 이 단계를 건너뛴다.

---

## 품질 기준

- [ ] 전체 대상 테스트를 빠짐없이 검토했는가
- [ ] 테스트명이 조건·행위·기대값을 포함하는가
- [ ] 테스트명이 사용자 언어로 작성 가능한 환경에서 사용자 언어를 사용했는가
- [ ] 5가지 불필요 기준 각각을 모든 테스트에 적용했는가
- [ ] 제거 권장과 수정 권장을 명확히 구분했는가
- [ ] 사용자가 각 권장 이유를 이해할 수 있도록 설명했는가
- [ ] 모든 변경이 사용자 확인 후 적용되었는가
- [ ] Before/After가 명확히 제시되었는가
- [ ] 수정 사항이 있는 경우 전체 테스트를 실행하여 통과를 확인했는가
