# Game Plan

기능 요청을 받아 프로젝트 환경에 맞는 **순차적 작업 체크리스트**를 생성하는 스킬.

작업은 코드 작업과 비코드 작업 구분 없이 **의미 있는 작은 단위**로 분해한다.
하나의 태스크 = 하나의 명확한 결과물 (파일 생성, 에셋 완성, 설정 완료 등)

---

## 전제 조건

- **인풋**: 기능 요청 (자유 텍스트 또는 기능 설명)
- **컨텍스트**: `DEV_ENV.md`
- **아웃풋**: `Docs/Features/{FeatureName}.md` — 체크리스트 형태의 작업 명세서

---

## 워크플로우

### Step 1: DEV_ENV.md 존재 확인

```bash
find . -name "DEV_ENV.md" -maxdepth 3 2>/dev/null
ls /mnt/user-data/uploads/DEV_ENV.md 2>/dev/null
```

**없는 경우**: 아래를 안내하고 중단한다.

> "DEV_ENV.md가 없습니다. game-env-analyzer 스킬을 먼저 실행해 주세요.
> '프로젝트 분석해줘'를 입력해 생성한 뒤, 파일을 업로드해 주세요."

**있는 경우**: 파일 전체를 읽어 다음 정보를 추출한다.
- 폴더 구조 및 파일 생성 위치 규칙
- 네이밍 규칙 (클래스, 메서드, 파일, 에셋)
- 사용 중인 패키지 및 프레임워크
- 핵심 아키텍처 패턴 및 코딩 컨벤션
- 프로젝트 고유의 수동 작업이 필요한 항목

### Step 2: 기능 목표 확인

사용자의 기능 요청에서 다음을 판단한다.

- 이 기능이 **왜** 필요한가 (목적)
- 이 기능이 완료됐을 때 **무엇이 달라지는가** (목표)

위 두 가지가 불분명하면 작업 분해로 넘어가지 않고 **목표가 명확해질 때까지 질문**한다.
질문은 한 번에 하나만 한다.

목표가 명확히 확정된 뒤 Step 3으로 진행한다.

### Step 3: 기능 요청 분석

기능 목표를 바탕으로 다음을 파악한다.

- **기능의 범위**: 이 기능이 어디서 시작해서 어디서 끝나는가
- **필요한 작업 목록**: 코드, 에셋, 설정, 수동 작업 등 모든 작업을 나열
- **외부 의존성**: 새로운 패키지, 에셋, 설정 파일 등이 필요한가
- **수동 작업**: DEV_ENV.md 기준으로 사람이 직접 해야 하는 작업이 있는가

### Step 4: 작업 분해

**분해 기준**
- 하나의 태스크 = 하나의 명확한 결과물
- 태스크 하나를 완료하는 데 30분~2시간 내외가 되도록 크기 조절
- 의존 관계에 따라 순서를 정한다
- DEV_ENV.md의 네이밍 규칙, 폴더 구조, 패턴을 그대로 적용한다

**단계 구성 원칙**

DEV_ENV.md에서 파악한 아키텍처, 패턴, 환경을 기반으로 단계를 구성한다.
단계 이름과 순서는 프로젝트 환경과 기능 특성에 맞게 자유롭게 정한다.
불필요한 단계는 생략한다.

### Step 5: 작업 명세서 작성

`references/plan-template.md`를 읽어 템플릿을 참조한 뒤, DEV_ENV.md의 실제 프로젝트 정보를 적용해 작업 명세서를 작성한다.

### Step 6: 사용자 확인

작성된 작업 명세서 전체 내용을 사용자에게 보여주고 승인을 요청한다.

```
📋 작업 명세서: Docs/Features/{FeatureName}.md
─────────────────────────────────────────
{작업 명세서 전체 내용}
─────────────────────────────────────────
이 계획으로 진행할까요?
1) 확정 (파일 저장)
2) 수정 후 재확인 (수정할 내용을 알려주세요)
3) 취소
```

- **1) 확정**: Step 7으로 진행.
- **2) 수정 후 재확인**: 요청한 내용을 반영한 뒤 다시 보여주고 재확인한다. 확인 완료 시 Step 7으로 진행.
- **3) 취소**: 파일을 저장하지 않고 종료한다.

### Step 7: 파일 저장 및 전달

- 저장 경로: `Docs/Features/{FeatureName}.md` (영문, PascalCase)
- `present_files`로 사용자에게 전달

## 품질 기준

완성된 작업 명세서는 다음을 충족해야 한다.

- [ ] 타이틀 바로 아래 "완료 체크" 섹션에 단일 체크 항목이 포함됨
- [ ] 모든 태스크에 파일 경로 또는 작업 대상이 명시됨
- [ ] DEV_ENV.md의 네이밍 규칙과 폴더 구조가 적용됨
- [ ] DEV_ENV.md에 없는 패턴이나 도구가 태스크에 포함되지 않음
- [ ] 각 태스크가 독립적으로 완료 가능한 크기임
- [ ] 기능에 불필요한 단계는 생략됨
- [ ] 개발자가 이 체크리스트만 보고 순서대로 작업할 수 있는 수준
