# Game Init

프로젝트의 개발 환경에 맞는 규칙 파일을 `.claude/rules/`에 심볼릭 링크로 연결하는 스킬.

---

## 전제 조건

- **인풋**: 없음 (호출만으로 동작)
- **아웃풋**: `.claude/rules/` 디렉토리에 규칙 파일 심볼릭 링크 생성

---

## 워크플로우

### Step 1: 개발 환경 확인

`Docs/DEV_ENV.md` 파일을 확인한다.

**파일이 있는 경우** — 파일을 읽어 개발 환경(엔진/언어)을 파악하고 Step 2로 진행한다.

**파일이 없는 경우** — `game-env-analyzer` 스킬을 먼저 실행하여 `Docs/DEV_ENV.md`를 생성한 뒤 Step 2로 진행한다.

---

### Step 2: 환경과 플러그인 매칭

감지된 개발 환경을 기반으로, 설치된 플러그인 중 해당 환경에 대응하는 플러그인을 결정한다.

| 감지된 환경 | 대응 플러그인 |
|------------|--------------|
| Unity | unity-plugin |
| Phaser | phaser-plugin |

대응 플러그인이 없는 환경이라도 game-plugin 자체의 규칙 파일은 항상 대상에 포함한다.

---

### Step 3: 규칙 파일 탐색

대상 플러그인들의 `rules/` 디렉토리에서 규칙 파일(`.md`)을 탐색한다.

탐색 대상:
1. **game-plugin** — 항상 포함
2. **대응 플러그인** — Step 2에서 결정된 플러그인

```bash
# 예: game-plugin과 unity-plugin의 규칙 파일 탐색
find {game-plugin경로}/rules -name "*.md" 2>/dev/null
find {대응플러그인경로}/rules -name "*.md" 2>/dev/null
```

**규칙 파일이 없는 경우** — 아래를 출력하고 종료한다:

```
ℹ️ 연결할 규칙 파일이 없습니다.
```

**규칙 파일이 있는 경우** — Step 4로 진행한다.

---

### Step 4: 심볼릭 링크 생성

#### 4.1 디렉토리 확인

```bash
mkdir -p .claude/rules
```

#### 4.2 기존 링크 확인

`.claude/rules/` 에 이미 같은 이름의 파일이 있는지 확인한다.

- **심볼릭 링크가 이미 존재하고 같은 대상을 가리키는 경우** — 건너뛴다 (이미 연결됨)
- **심볼릭 링크가 존재하지만 다른 대상을 가리키는 경우** — 기존 링크를 제거하고 새로 생성한다
- **일반 파일이 존재하는 경우** — 덮어쓰지 않고 사용자에게 알린다:

```
⚠️ .claude/rules/{파일명}이 이미 일반 파일로 존재합니다.
   플러그인 규칙을 연결하려면 기존 파일을 먼저 제거해 주세요.
```

#### 4.3 링크 생성

각 규칙 파일에 대해 프로젝트 루트 기준 상대 경로로 심볼릭 링크를 생성한다.
플러그인 이름을 접두어로 붙여 출처를 명확히 한다.

```bash
# 예: unity-plugin/rules/code-style.md → .claude/rules/unity-plugin--code-style.md
ln -s {플러그인rules파일의상대경로} .claude/rules/{플러그인명}--{파일명}
```

**이름 규칙**: `{플러그인명}--{원본파일명}`
- 예: `unity-plugin--code-style.md`, `phaser-plugin--code-style.md`, `game-plugin--code-style.md`

---

### Step 5: 완료 보고

```
✅ 규칙 파일 연결 완료

   📁 대상: .claude/rules/
   🔗 연결된 파일:
   - {플러그인명}--{파일명} → {원본 경로}
   - ...

   ⏭️ 건너뛴 파일: (있는 경우)
   - {사유}
```

---

## 주의사항

- 규칙 파일을 복사하지 않고 **심볼릭 링크**로 연결한다. 플러그인 업데이트 시 자동 반영된다.
- `.claude/rules/`에 이미 존재하는 일반 파일은 절대 덮어쓰지 않는다.
- game-plugin의 규칙 파일은 환경과 무관하게 항상 연결 대상에 포함한다.
- 환경에 대응하는 플러그인이 설치되어 있지 않으면 해당 환경의 규칙은 건너뛴다.
